# SVG 시작 잔선·마그네틱 수직 추적 수정 검증

## 범위

사용자가 요청한 두 문제만 수정한다. 외형 일치, SaaS 모션, 다른 기법과 조합기 동작은 변경하지 않는다.

- SVG: 임의 도형에 고정 dash 길이 320을 사용하면 경로 일부가 처음부터 보이는 문제.
- 마그네틱: X 오프셋이 0인 수직·중심 이동을 마우스 이탈로 잘못 판단해 450ms 곡선을 사용하는 문제.

## 변경

- SVG 데모 path에 `pathLength="1"`을 지정하고 관련 CSS의 dasharray·초기 dashoffset을 1로 맞췄다. 복사용 프롬프트에도 동일한 길이 정규화를 요구한다.
- SVG의 2.4초 루프, 0~65% 선 그리기, 65~85% 채움, 85~100% 유지는 유지한다.
- 마그네틱은 좌표 값 대신 추적 상태를 기록한다. 모든 mousemove는 50ms ease-out, mouseleave는 오프셋 초기화와 450ms 탄성 복귀를 적용한다.
- `svg-draw`와 `animate-svg-draw` 참조를 검색했고 해당 SVG 데모 한 곳에서만 사용 중임을 확인했다.

## 자동 검증

- `npm test`: 12개 통과. 새 회귀 테스트는 순수 수직 이동 → 중심 통과 → 대각선 → 이탈 → 재진입 순서의 오프셋과 전환 시간을 검증한다.
- `npm run build`: TypeScript 검사 및 Vite 프로덕션 빌드 통과.
- `git diff --check`: 통과.

## 브라우저 검증

실제 데모 컴포넌트와 새 프로덕션 CSS를 로컬 브라우저의 360×160 프레임에서 실행했다. 수정된 SVG 프롬프트는 기존 데모·이전 결과를 보지 않은 새 에이전트에 전달해 한 번 독립 생성했다. 생성 결과를 비교 후 고치도록 요청하지 않았다.

19개 검사 전부 통과했다.

| 항목 | 관찰 |
| --- | --- |
| 이전 SVG 생성본 | 실제 경로 길이 332.42, dash 320. 0ms 외곽선 픽셀 74개 |
| 수정된 사이트 SVG | 실제 경로 길이 292.60, pathLength 1. 0ms 외곽선 픽셀 0개 |
| 수정 프롬프트 독립 재생성 | 실제 경로 길이 409.93, pathLength 1. 0ms 외곽선 픽셀 0개 |
| SVG 65% (1560ms) | 수정 데모·새 생성본 모두 dashoffset 0, 외곽선 표시 |
| SVG 85%·90% (2040/2160ms) | 수정 데모·새 생성본 모두 인디고 fill alpha 0.25 유지 |
| 수직 아래·위 | 중심에서 y ±24px 입력 → translateY ±10.08px, 50ms ease-out |
| 중심 | 오프셋 0이어도 추적 상태를 유지하며 50ms ease-out |
| 대각선 | (80,24)px 입력 → translate(33.6,10.08)px, 50ms ease-out |
| 이탈 | translate(0,0), 450ms cubic-bezier(0.34,1.56,0.64,1) |

픽셀 검사는 실제 path의 계산된 스타일과 pathLength·좌표를 직렬화해 브라우저 Canvas에 그린 뒤 alpha > 8/255인 픽셀을 집계했다. 실제 화면 캡처에서도 이전 생성본만 시작 잔선이 보이는 것을 확인했다.

마그네틱은 합성 마우스 이벤트를 입력하고 계산된 CSS 전환 시간과 오프셋을 검사했다. 비활성 iframe의 전환 진행이 지연되어 최초 측정에서는 좌표가 이전 프레임에 남았다. 이를 앱 실패로 간주하지 않고 CSS 전환을 명시적으로 완료시킨 뒤 최종 좌표를 검사했다. 전환 시간은 계산된 CSS 값이며 벽시계 재생 속도를 측정한 결과는 아니다.

## 한계

- 독립 재생성은 한 번이다. 모든 모델·도형·뷰포트에서의 성공을 보장하지 않는다.
- 브라우저 검증은 단일 프레임 크기와 다크 테마 중심이다. 터치·라이트 테마·전체 카탈로그 재현을 다시 평가하지 않았다.
- 로컬 검증용 HTML·원본 JSON·스크린샷은 이 대화의 시각화 작업 폴더에 보존했다. 운영 코드에는 실험용 도구나 생성 UI를 추가하지 않는다.
