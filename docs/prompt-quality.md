# 프롬프트 품질 기준

목표는 사용자가 선택한 **효과와 상호작용을 구현하는 것**이다. 데모는 효과를 설명하는 예시이며, 색상·문구·치수·배치의 완전 일치를 요구하는 디자인 명세는 아니다.

## 프롬프트에 담을 내용

- 효과를 적용할 요소와 마우스·클릭 등 입력 동작을 설명한다.
- 초기 상태, 전환 조건, 반복·완료·취소·복귀 동작을 구분한다.
- 이동 비율·재생 시간·지연·범위처럼 효과를 결정하는 수치와 조건을 빠뜨리지 않는다.
- 클릭·타이머 시연을 실제 드래그·스크롤 감지·인증·오디오 분석·요청 성공으로 설명하지 않는다.
- 기존 화면에 적용할 때는 지정한 대상의 맥락과 무관한 동작을 유지한다. 별도 요구가 없으면 데모의 문구나 외형을 그대로 복제할 필요는 없다.

## 검증할 내용

1. 원본 데모의 입력과 상태 전환을 프롬프트가 설명하는지 확인한다.
2. 프롬프트로 만든 결과에 입력을 주고, 효과·중요 수치·반복·복귀 조건을 비교한다. 외형 차이는 별도 요구가 있을 때 평가한다.
3. 원본을 보지 않은 최초 생성 결과를 사용했다면 생성 조건과 표본 수를 기록한다. 비교 후 고친 결과와 최초 결과를 구분한다.
4. 일반적인 입력 외에 시작·끝·중심·범위 경계도 확인한다. 생성 결과의 오류와 원본 데모·프롬프트 사이의 불일치를 구분한다.
5. 실제 실행한 범위와 미확인 범위를 기록한다. 일부 조건의 통과 수를 시각 유사도나 전체 카탈로그의 성공률로 표현하지 않는다.

## 구현에 따라 달라지는 조건

- SVG의 실제 경로 길이는 도형마다 다르다. 고정 길이를 임의 도형에 재사용하지 않고 `pathLength` 정규화나 실제 길이 계산 등 일관된 길이 기준을 요구한다.
- 마그네틱 효과의 추적·이탈은 입력 상태로 구분한다. 좌표가 0이라는 이유만으로 복귀 상태라고 판단하면 수직 이동이나 중심 통과에서 동작이 달라질 수 있다.

이 판단의 근거는 [재현 실험](tasks/prompt-reproduction/02-research.md)과 [SVG·마그네틱 수정 기록](tasks/svg-magnetic-fix/verification.md)에 보관한다. 구체적인 현재 동작은 코드와 테스트를 기준으로 확인한다.
