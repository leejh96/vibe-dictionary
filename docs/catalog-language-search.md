# 카탈로그 언어와 검색

웹과 MCP는 `@vibe-dictionary/catalog`의 번역 조회·검색 함수를 함께 사용한다. 별도 서버, AI API, 임베딩 또는 벡터 DB는 사용하지 않는다.

## 언어별 데이터

- `techniques.ts`: 기법 타입·분류와 import한 기법 배열의 조합. ID·한영 이름·한국어 원문은 `additions/base.ts`와 묶음별 모듈에서 관리한다. 기존 ID와 저장 형식은 유지한다.
- `translations/en.ts`: `translations/additions/`의 ID별 영어 요약·효과 태그·검색 키워드·프롬프트를 import해 합친다. 기본 기법은 `base.ts`에서 관리하며 타이밍·수치·입력·반복·종료·복귀와 시연의 한계를 한국어와 맞춘다.
- `localization.ts`: `Locale`, 언어별 분류명, `getTechniqueText(item, locale)`. 기본 언어는 `ko`다.
- `translations/classification.en.ts`: 영어 도메인·카테고리 이름. `localization.ts`의 `DOMAIN_NAMES`는 한국어와 영어 원문 모듈을 import해 연결한다.
- `apps/web/src/i18n/base.messages.ts`, `demos/*.messages.ts`: 기본 문구와 기법 묶음별 한영 문구를 고정 키로 관리한다.
- `messages.ko.ts`: 한국어 사전을 import해 합치고 키에서 `MessageKey` 타입을 만든다.
- `messages.en.ts`: 영어 사전을 import해 합친다. `satisfies Record<MessageKey, string>`으로 키 누락·오타·추가를 타입 검사한다.
- `messages.ts`: `translateMessage(locale, key, params)`와 키별 필수 자리표시자 타입. 미등록 키·필수 인자 누락은 원문으로 숨기지 않고 오류로 처리한다.
- `LocaleContext.tsx`: `LocaleProvider`와 `useLocale().t`로 화면의 언어를 연결한다. 분류명·기법 데이터는 공용 카탈로그의 안정된 ID로 조회한다.

웹 헤더 우측의 지구본과 KR/EN 버튼을 누르면 언어 메뉴가 열린다. 한국어 또는 English를 선택해 전환하며, 방향키·Home/End로 이동하고 Escape·바깥 클릭·포커스 이탈로 닫는다. 모바일에서는 조합기 문구를 아이콘·개수 배지로 줄이고 서비스 이름은 유지한다. 언어는 `vibe-dictionary-locale` 키에 저장하며 저장소가 차단돼도 전환은 동작한다. 조합기 ID·선택 순서·사용자 입력 대상은 언어 전환으로 바뀌지 않는다. 복사에는 선택 언어의 프롬프트를 사용한다. 타이핑 데모는 문장 언어가 바뀌면 타이핑을 처음부터 재생한다.

영어 기법 번역이 없을 때 조회 함수는 한국어 원문으로 돌아가지만, 전체 ID의 영어 번역·검색 메타데이터가 있어야 하는 회귀 테스트가 이를 배포 전에 검출한다. 새 기법을 추가할 때 번역을 미완료로 남기지 않는다.

확장 기법은 카테고리별로 `translations/additions/<category>.ts`와 `search-metadata/additions/<category>.ts`에서 관리하고 각각의 상위 파일에서 합친다. 기본 기법도 각 폴더의 `base.ts`에서 관리하며 상위 조합 파일에 개별 항목을 작성하지 않는다. 웹 데모 문구는 `apps/web/src/i18n/demos/<category>.messages.ts`, 기본 UI·기존 데모 문구는 `i18n/base.messages.ts`에 한영 쌍으로 둔다. 이 파일들은 번역 데이터로만 소스 문구 검사에서 제외하며, 합쳐진 사전의 키·빈 값·자리표시자·영어 내 한국어 검사는 그대로 적용한다. 메시지 키의 카테고리 구간은 `kineticAd`처럼 영문 camelCase를 사용한다.

## 웹·데모 문구 수정 방법

한국어 문구 자체를 키로 사용하지 않는다. 문구의 역할을 나타내는 키를 한 번 정하고, 표현을 수정해도 키를 유지한다. 기법 번역의 ID와 같은 원칙이다.

1. 한국어 사전에 키와 문구를 추가한다.
2. 영어 사전에 같은 키와 적절한 번역을 추가한다.
3. 컴포넌트에서 `const { t } = useLocale()` 후 고정 키를 호출한다.

```ts
// base.messages.ts의 BASE_KO_MESSAGES
'actions.copyPrompt': '프롬프트 복사',
'search.noResults': '현재 영역에 "{query}" 검색 결과가 없습니다.',

// base.messages.ts의 BASE_EN_MESSAGES
'actions.copyPrompt': 'Copy prompt',
'search.noResults': 'No results for "{query}" in this section.',
```

```tsx
<button>{t('actions.copyPrompt')}</button>
<p>{t('search.noResults', { query: searchQuery })}</p>
```

'프롬프트 복사'를 '구현 프롬프트 복사'로 바꾸더라도 `actions.copyPrompt` 키와 컴포넌트 호출은 그대로 둔다. 영어 문구의 의미도 변경이 필요한지 함께 검토한다. 서로 다른 문맥에서 다른 번역이 필요하면 별도 키를 쓴다.

숫자·검색어·사용자 입력은 이름이 있는 자리표시자로 전달한다. 한국어 어순의 문장 조각을 이어 붙이거나 완성된 문자열을 다시 번역하지 않는다. 번역 함수는 입력값을 재번역·재치환하지 않으므로 사용자가 입력한 한국어·중괄호 등은 유지된다. 조합 프롬프트의 적용 대상도 같은 방식으로 처리한다.

상태에는 ID·숫자·메시지 키를 보관하고 화면에 표시할 때 번역한다. 카드 순서·알림 번호·선택 액션을 유지한 채 언어를 바꿀 수 있어야 한다. 문장 전체를 저장하는 타이핑 데모는 언어 변경 시 새 문장으로 재생한다. 화면 전체에서 동일하게 유지할 영문 샘플 타이틀도 `sample.*` 키로 두고 한영 값을 같게 작성한다. 언어 메뉴의 한국어 자국어 이름·보조 표기는 의도적으로 양쪽에 동일한 한국어를 사용한다.

## 번역 누락 자동 검사

`npm run check:i18n`은 아래 조건에서 실패하며 웹 테스트와 웹 빌드 시작 시에도 자동 실행된다.

- 한국어·영어 사전의 키가 다르거나 값이 비어 있음.
- 같은 키의 `{query}`, `{count}` 등 자리표시자 이름이 다름.
- 영어 번역에 한국어가 남음. 언어 메뉴의 의도된 자국어 표기만 동일 값인지 확인해 예외로 둔다.
- 번역 사전 밖 웹 소스에 한국어 문자열·템플릿·JSX 텍스트가 있음. 주석은 제외한다.
- JSX에 영문 텍스트를 직접 넣거나, 표시용 문자열·title/aria-label/placeholder/alt를 직접 작성함. CSS·클래스·기술 속성은 구분한다.
- 미등록 리터럴 키 또는 이전 `tr(원문)` 호출을 사용함.

타입 검사는 잘못된 키, 필수 자리표시자 누락·이름 오류, 영어 사전의 전체 키를 검사한다. `npm run test:web`은 실제 앱과 타입 오류 예제도 컴파일해 이 계약이 유지되는지 확인한다. 누락·빈 값·자리표시자 변경·직접 작성한 문구를 검사기가 거부하는 테스트도 포함한다.

자동 검사는 번역 의미의 정확성·최신성이나 임의의 변수·함수를 거쳐 전달되는 모든 영문 문자열의 용도를 판단하지 못한다. 카탈로그 데이터와 사용자 입력은 별도 경로로 관리하므로 UI 소스 검사 대상과 구분한다. 리뷰 시 새로운 표시 문구가 고정 키를 사용하는지와 실제 화면을 함께 확인한다.

## 검색 메타데이터

`search-metadata/additions/base.ts`와 묶음별 모듈에서 기법별 정보를 관리하고, `search-metadata.ts`는 타입·분류와 import한 목록의 조합·조회를 담당한다.

| 필드 | 의미 |
| --- | --- |
| `aliases.ko/en` | 같은 효과를 부르는 추가 별칭 |
| `targets` | `button`, `card`, `text` 같은 언어 독립 적용 대상 |
| `triggers` | `pointer-move`, `hover`, `click`, `hold`, `drag`, `input`, `auto`, `static` 중 실제 데모의 입력·실행 방식 |
| `useCases.ko/en` | 언제 무엇을 표현하려고 쓰는지 설명하는 문장 |

이름에 scroll/drag/audio가 있어도 실제 데모가 클릭·타이머 시연이면 해당 입력으로 기록한다. 사용 상황은 실제 데모와 프롬프트에 근거하며 요약문을 복사하지 않고 사용 목적·배치 맥락을 설명한다. 별칭은 한영 모두 제공하고 같은 개념의 일상 표현과 전문 용어를 연결한다. 적용 대상과 효과 이름을 동의어로 취급하지 않는다.

## 관련도 검색

`searchTechniques({ query, domain, category, target, trigger })`가 웹과 MCP의 공통 키워드 검색 진입점이다.

1. NFKC와 소문자로 검색어를 정규화하고 `SEARCH_SYNONYMS`의 한영 동의어를 하나의 개념으로 연결한다. 일부 요청용 단어·조사는 제외한다. 일반적인 한국어 형태소 분석이나 의미 추론을 하는 검색은 아니다.
2. 지정한 필터는 모두 만족해야 한다. 검색 언어는 표시 언어와 무관하며 한영 데이터 전체를 검색한다.
3. ID·이름의 정확한 일치와 별칭 일치를 우선한다. 단어별 가중치는 이름 30, 별칭 28, 키워드 20, 사용 상황 18, 요약 12, 대상 8, 입력 6, 프롬프트 본문 1이다. 같은 단어는 가장 높은 필드 점수 한 번만 계산한다.
4. 정확한 일치가 없으면 유효 검색 단어의 60% 이상이 일치해야 한다. 관련도 점수는 일치 단어 가중치·검색어 충족 비율·정확한 일치 가점을 합한 정렬용 수치이며 적합성 확률이 아니다.
5. 검색어가 있으면 점수 내림차순, 동점은 카탈로그 순서다. 검색어 없이 조회하면 기존 카탈로그 순서를 유지한다. 일치가 없을 때 전체 목록으로 대체하지 않는다.

MCP 검색은 `score`, 일치한 필드명 `matchedOn`, 적용 대상·입력·해당 언어의 사용 상황을 제공한다. 검색 결과에 프롬프트 전문을 넣지 않으며 선택한 ID만 `get_technique`로 조회한다. 원문의 단어가 우연히 일치한 후보도 있을 수 있으므로 LLM은 상위 후보의 요약과 사용 상황을 비교해야 한다. 모호한 요청은 조건을 재구성하거나 사용자에게 확인한다.

MCP의 서버 지침과 도구 설명은 추상적인 디자인 요청을 사용자가 밝힌 목적·선호에 따라 구체적인 검색 후보로 바꾸도록 안내한다. `깔끔한` 같은 표현을 특정 스타일 하나로 고정하지 않으며, 판단에 필요한 맥락이 부족하면 확인한다. 여러 기법을 조합하는 요청은 스타일·레이아웃·상호작용 등 독립적인 요구별로 나누어 검색한다. 예를 들어 미니멀 스타일과 벤토 레이아웃이 요청에 적합하다면 `minimal`과 `bento grid`를 각각 검색한다. 선택한 기법의 프롬프트를 조회한 뒤 적용 위치·시각적 표현·입력·타이밍의 충돌을 판단하는 주체는 호출한 LLM이며, MCP가 조합하거나 호환성을 검증하는 것은 아니다.

자연어 요청은 호출하는 AI가 해석한다. AI가 한 효과를 나타내는 짧은 한영 검색어를 생성 → MCP가 키워드로 후보 조회 → AI가 요약·사용 상황을 비교하고 필요하면 동의어·다른 언어·수식어를 줄인 표현으로 재검색 → 선택한 ID의 프롬프트를 조회한다. 예를 들어 “글을 고친 뒤 아직 저장하지 않았다는 표시”는 `저장 상태` 또는 `unsaved changes`로 검색한다. 필수 조건은 유지하고 불필요한 필터만 넓히며, 검색어나 필터를 바꾸면 `offset: 0`부터 조회한다. 순위가 높아도 요구에 맞지 않으면 선택하지 않는다.

MCP 내부에는 검색어 생성 모델이나 벡터 검색이 없다. 이 역할 분담은 서버 지침과 도구 설명으로 호출하는 AI에 안내한다.

## 추가·수정과 검증

기법 데이터·영어 번역·검색 메타데이터·실제 데모를 함께 대조한다. 새 UI/데모 문구는 공통 언어 Context의 `t(key, params)`로 표시한다. 컴포넌트 상태에는 ID·숫자·고정 메시지 키를 유지하고 출력 시 번역해 언어 전환 후 이전 언어가 남지 않게 한다. 사용자 입력은 번역하지 않는다.

- `npm run check:i18n`: 한영 키·빈 값·자리표시자·영어 내 한국어·웹 소스 문구 규칙.
- `npm run test:catalog`: 번역·메타데이터 전체 ID 일치, 대표 한영 질의의 1순위, 무관 질의, 필터와 중요한 프롬프트 조건.
- `npm run test:web`: 기존 복사·저장 계약, 언어 복원·저장소 차단·복사 중 언어 전환, 영어 조합기, 전체 데모의 초기·클릭·일부 타이머 상태, 상태 유지 중 언어 전환, 검사기의 실패 조건·타입 계약.
- `npm run test:mcp`: 실제 stdio 연결에서 언어 입력 검증·순위·페이지·전체 한영 원문 조회.
- `npm run build`, `npm run check:package`: 타입·번들·독립 설치 검증.

자동 테스트는 번역의 모든 의미나 전체 브라우저 레이아웃·애니메이션을 보장하지 않는다. 브라우저에서 한영 전환, 라이트·다크, 좁은 화면, 검색·복사·새로고침 복원을 확인한다.

## 로컬 MCP 확인

소스를 수정해도 이미 연결된 npm 고정 버전이나 실행 중인 MCP는 바뀌지 않는다. 이 저장소에서 `npm ci`와 `npm run build:mcp` 후 클라이언트에 `node <저장소 경로>/apps/mcp/dist/index.js`를 등록하고 MCP를 재시작해야 로컬 변경을 쓸 수 있다. npm 게시와 전역 설정 변경은 별도 작업이다.
